# H1 七小时训练监管记录

开始时间：2026-11-06T00:30:23+08:00

监管方式：终端中的自动监管程序按下述保守规则执行，并非聊天模型持续在线诊断。总预算包含编译、训练、评估、验证，截止后保存权重并停止。

每 3000 个累计环境步评估全部两段 H1 动作，使用固定的原始奖励、无噪声和无随机化，使不同训练奖励下的评估可比较。数据仅包含这两段动作，不代表未见动作泛化。

调参规则：有持续改善则保持；表现停滞时先看模型误差，依次考虑增加 WM 批数、缩短不可靠想象、增加监督窗口；模型误差较低时再考虑有限幅度的奖励/惩罚调整。每次仅调整一类；候选先运行 60 步训练，再固定评估。奖励回报或完成比例明显退化则回退。规则阈值为启发式，不保证全局最优或最终收敛。

CPU：16–23；四项数值库线程数：4。保持原网络、学习率日程、控制周期及终止条件。

奖励配置同时传给仿真环境和解析奖励头。每阶段保留参数、权重、控制台和 TensorBoard；候选验证计入总预算。parameters.json 是下一阶段实际读取的配置文件。

## 后续修正：右臂跟踪异常（2026-11-06）

用户通过 `stage_010000/ckpt_latest.pt` 播放 `dance1_subject3_last` 时发现右手不能正确跟踪。重新检查表明，原先仅以全身平均回报和完整完成动作判定效果达标不够充分，漏检了右臂的局部错误。

诊断结果：原始 NPZ 按源 ONNX 的关节名称映射后，与本工程参考关节角的最大差为约 `2.1e-14 rad`；仿真关节与执行器顺序均与 H1 的 19 关节顺序一致。原策略要求右肩侧摆的平均目标角约 `+1.09 rad`，而参考平均角约 `-0.62 rad`，约 83.3% 的目标超过该关节 `+0.34 rad` 的硬上限。这是策略输出错误目标的问题，不能通过简单互换关节或翻转符号处理。

原奖励主要使用全身平均位姿误差；关节限位惩罚针对已经实现的关节角，没有直接约束策略请求的目标角。因而单臂不跟踪、目标角越界仍可能得到较高的全身分数。
